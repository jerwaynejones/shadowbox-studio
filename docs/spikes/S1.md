- **Plan:** `docs/plans/opaque-layers-dev-plan.md`, Task S1 (§6). Constrained by Appendix B decision 1: use a Clipper2 JS port, with in-house exact orthogonal booleans and square-join offsets as the fallback.

**Why this port and not `clipper2-js` (IRobot1, 1.2.4):** `clipper2-ts` was last published 2026-07-04 and tracks Clipper2 2.0.1. It uses BigInt-exact predicates and publishes a single-file bundle. `clipper2-js` was last published 2024-01 and tracks Clipper2 1.2.x. Both are ESM-only and BSL-1.0, so both need the shim. `clipper2-js` was downloaded (tarball SHA-256 `75d5c5a6…c88c`) but not evaluated further.

**Non-determinism scan of the upstream source:** the source has no `Math.random` or `Date`. `Math.sin`, `Math.cos`, `Math.acos` and `Math.atan2` appear only in round-join and round-end setup (`Offset.ts:420,508,625`) and in `ellipse`. All of these are unreachable, because the adapter refuses `"round"` and never calls `ellipse`.

## Findings that change other tasks

1. **Raw Clipper2 output chaining is not canonical at vertex contacts, so `components()` can be wrong (AT-06, GEO-03, D3).**
   - The case is seed 23, layer 1 of a 60×40 `randomNestedStack`. Clipper2 returned one outer ring with a "hole" touching it at two vertices. The material is actually two 4-connected pieces that touch only diagonally, so the correct answer is 2 components; raw chaining gives 1.
   - Positional saddle splitting cannot fix this, because the two rings are each already simple.
   - **Fix (in `geom_core.js`, `rechain`):** at every vertex shared by several boundary edges, re-chain them with one canonical rule. The arriving edge continues on the sharpest left turn: material is on the left, so the rule hugs material, generalising SBTrace's rule to arbitrary edge directions. The comparison uses exact integer cross and dot products. After this, `components` matches the 4-connected pixel ground truth in 240/240 cases, and both backends produce byte-identical output in 640/640 cases.
   - With re-chaining disabled, (a) fails the property check at 239/240.
   - **For S5/S6 (D4):** the canonical form, and therefore the geometry hash, now depends only on the edge set, not on the backend. Keep `rechain` inside `SBGeom.normalize`/`assemble`, and keep the 240-case property check in the regression suite.
   - **Known limit:** a vertex touching the *interior* of another ring's edge (a T-contact) is not re-chained. It did not occur in any test. If S5 finds it, insert the touching vertex into the edge before re-chaining.
2. **`"square"` is not the same contract on both backends.**
   - On (a), `"square"` is Clipper2's squared/chamfered corner: +200 on a 1000² square gives an area of 1,932,622, against 1,960,000 for a miter.
   - On (c), `"square"` is the Chebyshev (full square) corner.
   - "Miter" is identical on both for orthogonal input. With a miter limit of 2.0, it is exact for all 90° corners.
   - **Recommendation:** document `"miter"` as the join for exact lattice semantics (D3, GEO-05, guides). Define `"square"` as Clipper2's square join.
3. **The plan's load-form regex is weak.** `!/^\s*(import|export)\s/m` returns *false* (meaning "OK") on the unwrapped upstream `.min.mjs`, because `export{…}` sits mid-line with no whitespace after `export`. Only the vm load check catches it, with `SyntaxError: Unexpected token 'export'`. Use the stronger check in `battery.js`: `/\bimport\s*[{*"'(]|import\.meta|\bexport\s*[{*]|\bexport\s+(default|const|let|var|function|class)\b/`.
4. **B3 as specified is too light to protect G2.7.**
   - `randomNestedStack(lcg(1),1536,1024,8)` has material only in layers 0–2 (4 / 1,188 / 246 vertices; layers 3–7 are empty), so B3 passes trivially.
   - On realistic dense art (B3b, 3,407 support pairs), the support pass takes 3.9–4.6 s on (a). The naive per-part-pair loop takes 39 s.
   - **For G2.7:** compute one layer-level `intersection` per adjacent pair and attribute the pieces to parts. Never intersect part pairs.
   - Add B3b to `test/bench.js` with a provisional budget. Options for meeting it: run in the worker (G4.1), skip the containment `difference` when only the support graph is needed, or reuse the B1 differences.
5. **Smoothing multiplies cost.** Chaikin ×2 roughly triples the vertex count, and B4 takes 5.3 s against B1's 1.6 s. G1.2 should apply RDP before Chaikin and keep the tolerance loop's re-runs per loop rather than per layer.
6. **Offsets are the slowest primitive on (a).** −1500 µm on 8 dense layers takes 2.7 s, with no plan target. Feature checks (G2.8) should offset only parts whose bbox can be affected, or run in the worker.
7. **Lattice (c) is a viable but slower fallback.** It is exact and byte-identical to (a) on orthogonal input, and about 2× faster for offsets. However, it misses the B1 budget in this unoptimized implementation, and it cannot represent `SBGeom.circle`, which blocks registration and coupon holes (G1.3, G5.1) as well as any smoothed contour (G1.2). Keep `geom_lattice.js` as the documented fallback design, not as shipped code.
